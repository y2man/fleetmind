# Demo data (Phase 9)

A fictional company, "Selam Freight (Demo)", with 14 vehicles, 12 drivers, about 190 deliveries over the last 90 days (and the next few), about 220 fuel purchases, 25 maintenance records, several routes with stops and 3 geofences. Everything is marked `is_demo` and uses made-up names, plates and approximate Addis Ababa coordinates.

## Use it
| Where | How |
|---|---|
| Docker (development) | Automatic: `SEED_DEMO_ON_START=true` in `.env` runs it after migrations. Or `./scripts/seed-demo.sh` |
| Without Docker | `cd backend && alembic upgrade head && python -m app.seed` |
| Rebuild from scratch | add `--reset` (only the demo organization is deleted) |

Sign in at /signin (the page shows one-click buttons when `VITE_DEMO_LOGIN=true`). All four accounts share the password `FleetMind-Demo-2026`:

## What is deliberately wrong in it
So that alerts and AI screening have something to show. Open the bell once to raise the alerts.
- A vehicle with insurance expired 12 days ago, another with registration expiring in 9 days.
- A driver licence expired 9 days ago, another expiring in 18 days.
- A scheduled service 6 days overdue.
- Open deliveries past their deadline, plus some marked delayed.
- Vehicle ET-A1001: one fuel fill about 2.6 times its normal size. Vehicle ET-A1005: a purchase entered twice 25 minutes apart, and one odometer reading typed 900 km too low.

The generator keeps this list in `SeedData.planted`, and a test confirms the real alert and screening code finds each one.

## Behaviour and safety
- **Idempotent.** A second run changes nothing and says so.
- **Relative dates.** Dates are computed from "now", so data seeded today looks current. The same seed number gives the same data for the same day.
- **Never touches real data.** `--reset` deletes only the organization named "Selam Freight (Demo)", and refuses if anyone other than the four demo accounts has joined it. If a demo email is already used by another organization the seed stops instead of taking it over.
- **Refuses in production** (`ENVIRONMENT=production`) because the password is public. `--allow-production` overrides it for a deliberate public demo site; never do that on a site with real customers.
- No AI insights or reports are seeded: those are generated by the model, and showing invented model output as real would be misleading. Generate a report on the AI page.
- Live map positions are not seeded either; the simulator (Phase 6) moves Active vehicles once someone opens the map.
- The demo password is also in `frontend/src/config/demo.ts`; a test fails if the two drift apart.
